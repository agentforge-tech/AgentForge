# AgentForge 会话级权限审批存储扩展设计方案

> 状态：首期设计方案
>
> 本文是《AgentForge 权限体系与审核中断恢复设计方案》的补充，目标是以最小改动解决 `APPROVE_ALWAYS` 未按会话隔离的问题，并为业务方保留自定义审批授权存储能力。

## 1. 背景

当前 `PermissionInterruptModule` 使用实例字段保存 `APPROVE_ALWAYS`：

```java
private final Set<String> acceptedCalls =
        Collections.newSetFromMap(new ConcurrentHashMap<String, Boolean>());
```

权限预检时直接判断：

```java
acceptedCalls.contains(fingerprint(request));
```

审批恢复时直接添加：

```java
if (response.getAction() == ApprovalAction.APPROVE_ALWAYS) {
    acceptedCalls.add(fingerprint(interrupt.getToolRequest()));
}
```

当前 `fingerprint` 只包含工具名和原始参数，没有包含 `memoryId`：

```java
private static String fingerprint(ToolExecutionRequest request) {
    return request.name() + "\n" + request.arguments();
}
```

因此，如果一个 `PermissionInterruptModule` 被多个会话复用，会话 A 的 `APPROVE_ALWAYS` 可能影响会话 B。

首期不引入复杂的规则模型、动作注册表或新的审批状态机，只把“查询是否已授权”和“记录授权”抽取成核心接口，并提供按会话隔离的内存默认实现。

## 2. 首期设计结论

首期仍然只支持现有三种审批操作：

```java
public enum ApprovalAction {
    APPROVE_ONCE,
    APPROVE_ALWAYS,
    REJECT
}
```

三种操作的行为保持不变：

| 审批操作 | 当前冻结 Tool Call | 是否记录后续授权 |
| --- | --- | --- |
| `APPROVE_ONCE` | 执行 | 否 |
| `APPROVE_ALWAYS` | 执行 | 是，默认记录到当前会话的内存授权中 |
| `REJECT` | 不执行，写入拒绝 Tool Result | 否 |

本次只新增一个 SPI：

```text
PermissionApprovalStore
    +-- isApproved(chatContext, toolRequest)
    +-- addApproval(chatContext, toolRequest, approvalAction)
```

默认实现：

```text
InMemorySessionPermissionApprovalStore
    key = memoryId + toolName + rawArguments
```

其中：

- `memoryId` 作为当前会话标识；
- `executionId` 不参与长期授权判断，因为同一会话恢复后会产生新的执行 ID；
- `AgentChatContext` 原样传入 SPI，业务方可以读取 `memoryId`、`executionId`、请求信息和 extensions；
- 添加审批结果时同时传入 `ApprovalAction`，业务实现可以区分三种审批操作；
- 默认实现只保存在当前进程内，服务重启后授权丢失。

## 3. 核心扩展接口

建议放置在：

```text
cloud.changlu.agentforge.agent.governance.permission.spi
```

接口定义：

```java
package cloud.changlu.agentforge.agent.governance.permission.spi;

import cloud.changlu.agentforge.agent.domain.AgentChatContext;
import cloud.changlu.agentforge.agent.governance.interrupt.domain.ApprovalAction;
import cloud.changlu.agentforge.model.chat.message.ToolExecutionRequest;

/** APPROVE_ALWAYS 授权的查询与记录扩展点。 */
public interface PermissionApprovalStore {

    /**
     * 判断指定 Tool Call 是否已经获得长期授权。
     *
     * <p>实现可以使用 chatContext 中的 memoryId、executionId 或业务 extensions
     * 确定授权作用域。
     */
    boolean isApproved(
            AgentChatContext chatContext, ToolExecutionRequest toolRequest);

    /**
     * 处理并记录一次用户审批结果。
     *
     * <p>默认实现只持久记录 APPROVE_ALWAYS；APPROVE_ONCE 和 REJECT 不形成后续授权。
     * 自定义实现可以根据 action 做审计或其他附加处理，但不能改变 Core 的执行语义。
     * 保存失败时应抛出异常，Core 不应静默降级成 APPROVE_ONCE。
     */
    void addApproval(
            AgentChatContext chatContext,
            ToolExecutionRequest toolRequest,
            ApprovalAction action);
}
```

`ApprovalAction` 只需要传给 `addApproval`：预检调用 `isApproved` 时尚未发生本次
用户审批，它查询的是此前由 `APPROVE_ALWAYS` 形成的授权；恢复阶段调用
`addApproval` 时已有真实响应，因此必须把本次实际 `ApprovalAction` 一并传入。

首期只保留这两个核心方法，不增加撤销、查询列表、TTL、规则转换等接口。

后续如果业务需要，可以自行实现该接口，将授权保存到数据库、Redis 或业务权限中心；不需要修改 `PermissionInterruptModule`。

## 4. 默认会话级内存实现

建议放置在：

```text
cloud.changlu.agentforge.agent.governance.permission.support
```

默认实现按 `memoryId` 隔离授权：

```java
package cloud.changlu.agentforge.agent.governance.permission.support;

import cloud.changlu.agentforge.agent.domain.AgentChatContext;
import cloud.changlu.agentforge.agent.governance.interrupt.domain.ApprovalAction;
import cloud.changlu.agentforge.agent.governance.permission.spi.PermissionApprovalStore;
import cloud.changlu.agentforge.model.chat.message.ToolExecutionRequest;

import java.util.Collections;
import java.util.Set;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ConcurrentMap;

/** 单进程、按 memoryId 隔离的 APPROVE_ALWAYS 默认存储。 */
public final class InMemorySessionPermissionApprovalStore
        implements PermissionApprovalStore {

    private final ConcurrentMap<Object, Set<String>> approvedCallsBySession =
            new ConcurrentHashMap<Object, Set<String>>();

    @Override
    public boolean isApproved(
            AgentChatContext chatContext, ToolExecutionRequest toolRequest) {
        Object memoryId = requiredMemoryId(chatContext);
        Set<String> approvedCalls = approvedCallsBySession.get(memoryId);
        return approvedCalls != null && approvedCalls.contains(fingerprint(toolRequest));
    }

    @Override
    public void addApproval(
            AgentChatContext chatContext,
            ToolExecutionRequest toolRequest,
            ApprovalAction action) {
        if (action == null) {
            throw new IllegalArgumentException("approvalAction must not be null");
        }
        if (action != ApprovalAction.APPROVE_ALWAYS) {
            return;
        }
        Object memoryId = requiredMemoryId(chatContext);
        Set<String> newSet =
                Collections.newSetFromMap(
                        new ConcurrentHashMap<String, Boolean>());
        Set<String> approvedCalls = approvedCallsBySession.putIfAbsent(memoryId, newSet);
        if (approvedCalls == null) {
            approvedCalls = newSet;
        }
        approvedCalls.add(fingerprint(toolRequest));
    }

    private static Object requiredMemoryId(AgentChatContext chatContext) {
        if (chatContext == null || chatContext.getMemoryId() == null) {
            throw new IllegalArgumentException(
                    "chatContext.memoryId must not be null for permission approval");
        }
        return chatContext.getMemoryId();
    }

    private static String fingerprint(ToolExecutionRequest request) {
        if (request == null) {
            throw new IllegalArgumentException("toolRequest must not be null");
        }
        return request.name() + "\n" + request.arguments();
    }
}
```

默认实现延续当前判断语义：

- 三种 `ApprovalAction` 都会传入默认实现；
- `APPROVE_ONCE` 和 `REJECT` 不形成后续授权；
- 只有 `APPROVE_ALWAYS` 会写入会话级内存；
- 工具名必须相同；
- 原始参数字符串必须相同；
- 新增 `memoryId` 会话隔离；
- 不持久化；
- 不跨节点共享；
- 线程安全。

如果 `memoryId` 为空，默认实现直接抛出异常，不能退化成 Agent 实例全局授权。

## 5. `PermissionInterruptModule` 改造

### 5.1 字段调整

删除：

```java
private final Set<String> acceptedCalls = ...;
```

新增：

```java
private final PermissionApprovalStore approvalStore;
```

构造函数使用默认实现：

```java
private PermissionInterruptModule(Builder builder) {
    this.mode = builder.mode;
    this.engine =
            new PermissionEngine(
                    builder.rules, builder.ruleHandlers, builder.modePolicy);
    this.store =
            builder.store == null
                    ? new InMemoryAgentInterruptStore()
                    : builder.store;
    this.approvalStore =
            builder.approvalStore == null
                    ? new InMemorySessionPermissionApprovalStore()
                    : builder.approvalStore;
    this.askUserEnabled = builder.askUserEnabled;
}
```

### 5.2 权限预检

当前逻辑：

```java
} else if (acceptedCalls.contains(fingerprint(request))) {
    continue;
}
```

调整为：

```java
} else if (approvalStore.isApproved(context, request)) {
    continue;
}
```

完整顺序保持不变：

```text
1. ask_user 特殊处理
2. PermissionApprovalStore 查询当前会话是否已授权
3. 未授权时进入 PermissionEngine
4. 得到 ALLOW / DENY / ASK
```

`PermissionApprovalStore` 只表示用户通过 `APPROVE_ALWAYS` 形成的历史授权，不替代 `PermissionEngine` 的静态规则和 Mode 判断。

## 6. 恢复阶段传递 `AgentChatContext`

### 6.1 当前问题

当前 `PermissionInterruptModule.resolve(command)` 在 `ReActAgent` 构建恢复用 `AgentChatContext` 之前，就直接写入了 `acceptedCalls`。

如果 SPI 要接收完整 `AgentChatContext`，授权记录动作需要移动到恢复上下文创建之后。

### 6.2 推荐流程

`resolve` 只负责：

- 校验批次和响应；
- 校验三种 `ApprovalAction`；
- 执行 `PENDING -> RESUMING` 抢占；
- 返回冻结快照和响应映射。

不再在 `resolve` 内保存 `APPROVE_ALWAYS`。

```java
public ResolvedInterruptBatch resolve(
        InterruptBatchResumeCommand command) {
    // 校验响应
    // store.claim(batchId)
    // 不再修改 acceptedCalls
    return new ResolvedInterruptBatch(snapshot, responses);
}
```

新增方法：

```java
/** 使用恢复阶段的真实 ChatContext 分发用户审批结果。 */
public void applyApprovals(
        ResolvedInterruptBatch batch, AgentChatContext chatContext) {
    for (InterruptRequest interrupt : batch.getSnapshot().getInterrupts()) {
        if (interrupt.getType() != InterruptType.PERMISSION_APPROVAL) {
            continue;
        }
        InterruptResponse response = batch.responseOf(interrupt);
        approvalStore.addApproval(
                chatContext,
                interrupt.getToolRequest(),
                response.getAction());
    }
}
```

三种 `ApprovalAction` 都会传给 SPI，但 Core 的执行语义仍由
`ReActAgent` 控制：`APPROVE_ONCE/APPROVE_ALWAYS` 执行冻结调用，`REJECT`
写入拒绝结果。SPI 不能把 `REJECT` 改成执行，也不能把 `APPROVE_ONCE`
擅自扩大成长期授权。

`ReActAgent.applyInterruptBatch` 中的调用顺序调整为：

```java
PermissionInterruptModule.ResolvedInterruptBatch resolved =
        permissionInterruptModule.resolve(command);
AgentInterruptSnapshot snapshot = resolved.getSnapshot();

AgentChatContext context = buildInterruptResumeContext(snapshot);

permissionInterruptModule.applyApprovals(resolved, context);

// 按原始顺序执行批准项、写入拒绝项或 AskUser 结果
applyFrozenToolCalls(resolved, context);
```

这样权限查询和权限添加都会拿到对应运行阶段的 `AgentChatContext`：

| 阶段 | SPI 方法 | ChatContext 来源 |
| --- | --- | --- |
| 首次执行预检 | `isApproved` | 当前 `run/runStream` 的上下文 |
| 中断恢复 | `addApproval` | 根据中断快照恢复出的上下文，同时传入实际 `ApprovalAction` |
| 恢复后的后续预检 | `isApproved` | 新执行的上下文，`memoryId` 保持不变 |

## 7. Builder 扩展

在 `PermissionInterruptModule.Builder` 中新增：

```java
private PermissionApprovalStore approvalStore;

public Builder permissionApprovalStore(
        PermissionApprovalStore approvalStore) {
    if (approvalStore == null) {
        throw new IllegalArgumentException(
                "approvalStore must not be null");
    }
    this.approvalStore = approvalStore;
    return this;
}
```

默认使用方式不变：

```java
PermissionInterruptModule module =
        PermissionInterruptModule.safeDefaults()
                .ask("shell", ".*")
                .build();
```

此时自动使用 `InMemorySessionPermissionApprovalStore`。

业务自定义：

```java
PermissionInterruptModule module =
        PermissionInterruptModule.safeDefaults()
                .ask("shell", ".*")
                .permissionApprovalStore(
                        new DatabasePermissionApprovalStore())
                .build();
```

## 8. 业务自定义实现示例

业务方可以通过 `AgentChatContext` 中的会话和扩展字段决定授权范围：

```java
public final class DatabasePermissionApprovalStore
        implements PermissionApprovalStore {

    private final PermissionApprovalRepository repository;

    @Override
    public boolean isApproved(
            AgentChatContext context, ToolExecutionRequest request) {
        Object memoryId = context.getMemoryId();
        Object userId = context.getExtension("userId");
        return repository.exists(
                userId,
                memoryId,
                request.name(),
                request.arguments());
    }

    @Override
    public void addApproval(
            AgentChatContext context,
            ToolExecutionRequest request,
            ApprovalAction action) {
        repository.saveAudit(
                context.getMemoryId(), request.id(), action.name());
        if (action != ApprovalAction.APPROVE_ALWAYS) {
            return;
        }
        Object memoryId = context.getMemoryId();
        Object userId = context.getExtension("userId");
        repository.save(
                userId,
                memoryId,
                request.name(),
                request.arguments());
    }
}
```

首期 Core 不规定数据库结构，也不解释 `userId` 等业务字段。自定义实现自行保证：

- 线程安全；
- 会话或用户作用域隔离；
- 保存失败时抛出异常；
- 不因查询异常默认返回已授权；
- 不修改原始 Tool Call。

## 9. 异常与安全语义

### 9.1 查询异常

`isApproved` 抛出异常时必须 fail-closed：

- 不能按已授权处理；
- 推荐终止本轮权限预检并暴露明确异常；
- 不应静默回退到 `ALLOW`。

### 9.2 保存异常

`addApproval` 抛出异常时：

- 当前 Tool Call 不执行；
- 不允许自动把 `APPROVE_ALWAYS` 降级成 `APPROVE_ONCE`；
- 中断恢复失败并触发已有错误回调；
- 调用方可以根据后续状态处理方案重新发起审批。

### 9.3 会话标识

- 默认实现只信任 `chatContext.getMemoryId()`；
- 不从前端 `InterruptResponse` 接收会话 ID；
- 不使用 `executionId` 代替会话 ID；
- `memoryId` 为空时禁止记录长期授权。

## 10. 首期测试要求

### 10.1 同一会话命中授权

```text
会话 A APPROVE_ALWAYS shell("npm test")
会话 A 再次请求 shell("npm test")
期望：直接通过，不再中断
```

### 10.2 不同会话互相隔离

```text
同一个 PermissionInterruptModule
会话 A APPROVE_ALWAYS shell("npm test")
会话 B 请求 shell("npm test")
期望：会话 B 仍然产生权限中断
```

### 10.3 同一会话不同参数不命中

```text
会话 A APPROVE_ALWAYS shell("npm test")
会话 A 请求 shell("npm deploy")
期望：仍然产生权限中断
```

### 10.4 `APPROVE_ONCE` 不保存

同一会话再次执行相同 Tool Call 时仍然产生权限中断。

### 10.5 `REJECT` 不保存

拒绝只影响当前冻结 Tool Call，不生成 ALLOW 或 DENY 历史记录。

### 10.6 上下文传递

自定义 `PermissionApprovalStore` 应能在以下两个方法中获得正确的：

- `memoryId`；
- `executionId`；
- `AgentRequest`；
- `extensions`。

`addApproval` 还必须收到本次真实的 `ApprovalAction`，分别覆盖
`APPROVE_ONCE`、`APPROVE_ALWAYS` 和 `REJECT` 的测试。

### 10.7 并发安全

同一会话并发保存相同授权时不能报错，也不能产生不一致状态；不同会话并发审批时不能互相命中。

## 11. 实施范围

首期建议只完成以下改动：

1. 新增 `PermissionApprovalStore`；
2. 新增 `InMemorySessionPermissionApprovalStore`；
3. 删除 `PermissionInterruptModule.acceptedCalls`；
4. `preflight` 改为调用 `approvalStore.isApproved(context, request)`；
5. `resolve` 不再直接保存 `APPROVE_ALWAYS`；
6. 新增 `applyApprovals(resolved, context)`；
7. Builder 支持注入自定义 Store；
8. 增加同会话命中、跨会话隔离和自定义上下文传递测试。

首期不实现：

- 新的审批动作；
- 自定义 `actionCode`；
- Handler Registry；
- TTL 和授权撤销；
- 项目级、用户级或系统级规则模型；
- 权限规则建议与复杂 Matcher；
- 数据库持久化默认实现。

这套最小设计可以先解决当前跨会话授权问题，同时让业务方通过一个简单接口接管授权查询和保存逻辑，后续再根据实际需求扩展。
